# Architecture and maintainability audit — 2026-08-24

## Audit scope and method

Reviewed source configuration, Python and frontend manifests, runtime launch
scripts, FastAPI route map, migration code, authentication/session code, RAG
retrieval/generation controls, dashboard/tenant queries, workflow logic,
billing/tender integrations, test inventory, lint, packaging metadata, and
live local schema/readiness metadata. No passwords, tenant rows, or source
credentials were copied into this report.

## Verified strengths

- The API has a real local readiness contract, separate from basic health.
- RAG retrieval combines lexical and dense PostgreSQL paths, role ACL filtering,
  rank fusion, reranking, parent context, and citation validation.
- Dashboard aggregation explicitly separates plot and mapping dimensions; tests
  guard against presenting mapping records as unique tenants or active tenancies.
- Tenant filtering, sorting, pagination, and date validation are server-side.
- Agenda workflow state changes check source authority role, ownership, current
  state, and target officer. Workflow-linked chats cannot be deleted.
- Billing and tender features are source-backed and covered by focused tests.
- The project virtual environment passes dependency consistency and contains an
  editable installation of this project.

## Improvements applied in this audit

1. Declared the setuptools build backend and explicit `src` package discovery.
2. Added pytest `src` path support while retaining the documented virtualenv
   execution path.
3. Ignored known generated caches, runtime logs, Vite build output, and TypeScript
   build metadata without deleting any existing files.
4. Aligned CORS methods with the implemented authenticated `DELETE` chat route.
5. Replaced the obsolete README/readiness claims with current architecture,
   operations, API, project-map, and audit documentation.

## Current risks and required decisions

| Priority | Verified observation | Impact | Recommended next action |
| --- | --- | --- | --- |
| High for external deployment | `COOKIE_SECURE` defaults to false and the app is loopback-oriented. | Cookies must not be sent this way on a non-HTTPS/public deployment. | Require HTTPS, set secure cookies, and restrict allowed origins before exposure. |
| High data-governance | External Authority and Tenant login code can compare a supplied password with legacy database password fields when bcrypt is not usable. | The portal inherits source credential-storage risk. | Decide a source-system migration/SSO strategy; do not copy or normalize passwords inside this app without authority. |
| Medium resilience | RAG readiness depends on a locally installed Ollama embedding model, completion model, and CrossEncoder initialization. | The portal remains available but answer capability becomes not-ready when local AI dependencies fail. | Add monitored start-up/operational alerts and keep `/health/ready` in deployment checks. |
| Medium data governance | Tender workflow records are JSON files guarded by process-local locking. | Concurrent multi-process writers or host loss need an operational strategy. | Move tender state to a transactionally managed application table only after an approved schema migration. |
| Medium maintainability | `web/src/main.tsx` and `web/src/styles.css` are large, multi-feature files. | Feature changes can create merge/conflict and CSS-regression risk. | Extract one tested feature boundary at a time; start with shared UI utilities or feature modals, not a broad rewrite. |
| Low API compatibility | API version is `0.2.0` but Python package version is `0.1.0`. | Release/version reporting may confuse operators. | Choose a release versioning policy when preparing a formal release. |

## Non-actions by design

- No broad frontend component move was made: the current UI is live and a
  speculative rewrite would risk behavior regressions.
- No existing database table, artifact, user record, chat, workflow, or source
  export was deleted.
- No assumptions were made about the correctness of historical source dates,
  missing tenant fields, or business labels beyond the documented API logic.
- No reference-project code or data was modified.

## Validation boundary

This audit validates source structure and local service contracts. It does not
perform an authenticated UI walkthrough because that would require using a real
Authority/Tenant account. The build and endpoint checks establish application
readiness, not business-user acceptance of every protected screen.
